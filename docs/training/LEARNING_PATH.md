# Ribeira Academy learning path

Ribeira Academy is planned training content, not a separate software product.
It teaches use, interpretation and limits of the platform. Training never
authorizes a user to turn a modelled/satellite value into a field, laboratory or
legal fact.

## Tracks

| Track | Outcome |
|---|---|
| Producer / customer | Understand Farm360, maps, reports, alerts, uncertainty and how to request assistance. |
| Operator / support | Safely onboard, inspect provider/ingestion health, handle alerts and preserve audit/provenance. |
| Consultant / agronomic partner | Interpret soil/lab/sampling/suitability evidence and expert-validation boundaries. |
| Commercial | Qualify needs, present service boundaries and avoid promising planned functionality. |
| Developer | Set up locally, understand architecture/migrations/testing/providers/security and troubleshoot safely. |

## Evidence First

Every track must distinguish `OBSERVED`, `OFFICIAL_SOURCE`, `MANUAL_CONFIRMED`,
`CALCULATED`, `DERIVED`, `PREDICTED`, `UNKNOWN` and `INCONCLUSIVE`. In
particular, satellite context is not a chemical soil result, an alert is not a
diagnosis, an analysis area is not legal demarcation, and a hypothesis is not a
causal conclusion.

## User manual and contextual help plan

The future user manual covers adding a property, viewing a Digital Twin,
creating an analysis area, reading suitability/flood exposure/alerts/evidence,
generating a report, understanding missing data, and importing sensor/lab
information. Stable product screens should add contextual help with source,
last-updated time, uncertainty, evidence level and a documentation link;
unstable screens use reproducible textual examples before screenshots.
